# Acceptance contract and trust boundary

For a fixed many-sorted Horn theory H and caller-selected ground goals G,
the intended guarantee is: if checking succeeds, every goal in G has a finite
derivation using ground instances of rules in H.

For each step the checker verifies consecutive numbering, an existing rule,
the exact premise count, earlier-only references, and one consistent schema
assignment across the premises, any explicit bindings, and any stated
conclusion. A stated conclusion must be well sorted; an omitted one is built
by instantiating the rule, which fails if a conclusion variable is unbound.
Each result must exactly match a caller-selected goal, and all goals must be
reported exactly once. The proof cannot introduce declarations or rules.

## Mechanized soundness

[agda/Soundness.agda](../agda/Soundness.agda) models the checking algorithm
on plain trees and proves in Agda that acceptance implies a derivation of
every goal from ground instances of the rules:

```agda
soundness : (R : List Rule) (goals : List Term) (c : Certificate)
          → accepts R goals c ≡ just tt → All (Derivable R) goals
```

The model includes stated and inferred conclusions, explicit bindings,
schema matching against one assignment, earlier-only references, and goal
results. It is checked with `--safe --without-K --no-libraries`, so it uses no
postulates and no library code; `nix flake check` runs it. The file also
evaluates the model on the natural-number example in ordinary and compact form.

The model is not connected to the Rust code by a proof. Not modelled: textual
parsing, names, sorts (derivations in the model are unsorted; that every
instance used is well sorted rests on the Rust sort checks), `def` abbreviations (which
the Rust reader expands while parsing), and hash-consing. The Rust kernel is
written to follow the model step for step, and differential tests compare it
with the extraction-time kernel on random and mutated inputs.

## Hash-consed terms

The kernel stores every distinct ground term and judgment once in an arena and
refers to it by index. Two invariants carry the soundness argument over from
trees to indices:

1. **Well-sortedness by construction.** `Arena` nodes are created only through
   `Checker::make`, which checks the symbol's arity and every argument's sort.
   Every index therefore denotes a well-sorted ground term or judgment.
2. **Index equality is structural equality.** A node is a head symbol plus
   argument indices. Interning compares the complete node with the stored one;
   the hash only selects a probe position. Distinct terms can never share an
   index, regardless of hash collisions, and equal terms always do because
   their arguments already do (induction on term height).

With these, matching a variable against a term, comparing a binding, and
comparing a result to a goal are each one integer comparison, and the cost of
matching a rule is proportional to the size of its schemas.

Adversarial inputs can force hash collisions and slow checking down; they
cannot change a verdict.

## Components

- `src/kernel.rs`: theory validation, sorting, hash-consing, matching,
  instantiation, reference and goal checks.
- `src/lex.rs` and `src/sexp.rs`: the one lexer used for theories, goals and
  proofs, and the S-expression reader for theories.
- `src/bin/kernel.rs`, `src/bin/stream-kernel.rs`: input and execution
  boundary; both read proofs incrementally.
- `src/replay.rs`: a compatibility wrapper around `check_reader`. The former
  chunked replay layer, with its scratch-file admissions and reserialization,
  is no longer part of the trusted code.
- Selected theories and goals: caller-controlled mathematical specification.
- Rust compiler, libraries, operating system, hardware, and execution environment.

Certificate producers do not need to be trusted for logical acceptance. This
includes `src/compress.rs` and `horn-compress`. It also includes oracle
certificates: `src/oracle.rs`, `horn-oracle`, and the decoding thread of
`oracle-kernel`. That thread only writes a compact certificate into a pipe,
and the kernel reads and checks the certificate as it would a file (see
[ORACLE.md](ORACLE.md)). An incorrect or inconsistent
supplied theory can still derive its consequences; the checker does not
validate its intended semantics or consistency.

## Trust budget of the cubical language

What a reader must trust to believe a result of `horn cubical eval`, measured
on this branch:

| Component | Size | Role |
| --- | ---: | --- |
| Ground kernel: `kernel.rs`, `sexp.rs`, `lex.rs`, `bin/kernel.rs` | 759 lines | Trusted code; [Soundness.agda](../agda/Soundness.agda) models the algorithm (not the Rust) |
| Core cubical theory (`cubical::core_theory`) | 404 rules | Trusted specification; adequacy for cubical type theory is a separate obligation |
| Rules generated by `data` declarations | 21 to 64 rules per script here | Trusted specification, written out with the certificate (`--emit`) |
| Rules generated by `def` | 7 rules per definition | Trusted specification, written out with the certificate; a definitional extension (below) |
| Schematic checker `schematic.rs` | 1,525 lines | Trusted only for `def-poly` claims "for every level"; modelled in [Schematic.agda](../agda/Schematic.agda); any instance unfolds to a ground certificate |
| Engine, elaborators, oracle coder, generalizer, compressor | about 17,000 lines | Untrusted: their output is checked |

Scripts are checked against a core theory derived from the bundled theory
(434 rules: the kamo3 snapshot, bool, nat, the circle, closed-term
weakening, scoped identities and equation weakening; the kamo3 replay
examples keep their snapshot fragments byte for byte) by two
mechanical reductions that cannot lose a derivable restricted judgment:

1. The unrestricted judgment layer is removed: the predicates `ctx`, `has`
   and `eq` and every rule whose conclusion or premises use them (29 rules:
   its typing and equality rules and the bridges `rhas.global`,
   `rhas.export`, ...). The restricted layer (`rctx`, `rhas`, `req`) states
   the same judgments under a face, no remaining rule mentions the removed
   predicates, and scripts only state restricted goals.
2. A rule that is an instance of another rule, with its premises among the
   instance's, is removed: `req.comp-nat-zero`, an instance of `req.comp-nat`.

A result depends only on the rules its derivation uses. Every script run
reports them (`relies on N of M rules`, and `--emit` writes `rules-used`):

A `def NAME TYPE TERM` is the constant `def/NAME` with seven generated
rules: its constructor, its structural rules (a closed atom is kept by every
shift and substitution), and

```text
(rule rhas.def/NAME ((rctx ?d ?g ?phi) (rhas z nil ft TERM TYPE))
  (rhas ?d ?g ?phi def/NAME TYPE))
(rule req.delta.def/NAME ((rctx ?d ?g ?phi) (rhas z nil ft TERM TYPE))
  (req ?d ?g ?phi def/NAME TERM TYPE))
```

Both rules have the definition's own closed typing as a premise, so the
constant can be used only in a derivation that also proves `TERM : TYPE`.
Reading `def/NAME` as `TERM` turns each generated rule into an instance of
valid reasoning: weakening a closed typing, and reflexivity. Adding them is
therefore a conservative, definitional extension; no axiom is added. Its
`TYPE` and `TERM` are the elaborated core terms, so a
definition's rules mention earlier definitions by their constants only.

The core theory also has four scoped
identities `shift.scoped`, `subst.scoped`, `dshift.scoped` and
`dsubst.scoped` ([scoped.horn](../theories/cubical/scoped.horn)), which
state in one step that a (dimension) shift or substitution at cutoff k leaves a term
unchanged when its free (dimension) variables are below k, as a `scoped`
judgment shows. They say what the structural rules mean, and they are
admissible: induction on the `scoped` derivation turns each `scope.X` step
into the premises of the matching structural rule with the term unchanged
(binders raise the cutoff and the scope bound together, and `shift` and
`dshift` are defined on every term, so the shifted replacement exists).
A test checks that every term former, including those that data
declarations generate, has its `scope`, `shift`, `subst`, `dshift` and
`dsubst` rules.
Most substitutions the engine performs pass over large closed library
terms; proving them this way roughly halves the certificates (circle.hcs:
967,033 to 500,909 steps). Some scripts now use fewer of the other rules,
since node-by-node substitution through some term formers is no longer
needed.

Equation weakening `req.shift`
([weakening.horn](../theories/cubical/weakening.horn)) is the counterpart of
`rhas.shift` for equations: an equation keeps holding under one more
ordinary binder, with its terms and type shifted. Weakening is admissible
for every equality rule; stating it lets the engine derive an equation once,
in the shortest context its terms live in, and lift it, as it already did
for typings. Without it, an equation carried under binders was derived again
at every depth: comparing a structure's types under a category's laws (up to
15 binders) made `Hom (op (op C)) x y ≡ Hom C x y` run for minutes. With it,
`op (op C) ≡ C` holds judgmentally and checks in about 5 s, and circle.hcs
drops from 289,598 to 153,575 steps.

The first seven scripts together use 337 rules (measured before the circle
was added). Each script now uses one more: `rhas.closed`, which weakens the
typing of a closed term in the empty context to any restricted context
([closed.horn](../theories/cubical/closed.horn)). It and `req.closed` are
the composite of variable weakening, dimension weakening and face
restriction, which are admissible for every rule of the theory; they are
stated as rules so that a closed library term is checked once. The circle's
composite loops add `req.s1rec-comp` (the recursor on a formal composition)
and reach universe composition, so they also use `req.comp-universe`,
Glue composition and `def.canonical-map`, whose program is now the direct
equivalence of a line built from transports and `iso-equiv`
([CUBICAL_SCRIPT.md](CUBICAL_SCRIPT.md#composite-loops)). The core rules they do not use
are the de Morgan equations they never need (`i.demorgan-*`, absorption,
distributivity, ...), some face weakenings, universe and path composition,
and a few Glue equations; these are ordinary parts of the theory that the
examples simply do not reach.

## Limits

Tests and the Agda model do not prove the Rust implementation correct.
Decoding an oracle takes time and memory proportional to the derivation it
expands to, which can be far larger than the oracle itself. Memory
is proportional to the number of steps and distinct subterms, which is small
for the certificates measured but not bounded by a constant. Parsing limits
do not provide complete resource isolation.

No semantic soundness theorem for a downstream type theory, normalization
result, or consistency result follows solely from certificate acceptance.
